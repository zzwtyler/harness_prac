# Ollama 模型适配与接入前实验记录

核查日期：2026-09-30。前半部分为官方资料与代码协议比较；文末补充本机安装与真实测试结果。

本文记录 Tev1 原生决策与 confidence 级联接入前的代码和实验环境，参数、默认模型与建议均指当时版本。当前实现使用 Tev1 决策、Qwen3.5 标注与 Qwen3:8b 级联，运行方式见 [项目 README](../README.md)，协议见 [架构文档](ARCHITECTURE.md)。

## 接入前代码的协议

当时默认模型为 `qwen3:4b`，`think=False`。第一阶段生成 `input_kind` 和多个 `intent + clause_indices`；第二阶段为每个意图选择子类型和各字段的原文索引列表，Python 再复制原文。相同业务类别也可能有多个独立目标，共享片段可以归属多个目标。这不是单次九选一分类。相关模块为 `core/08_extraction.py`、`core/04_instructions.py`、`core/15_models.py`，仓库中的这些文件已随后续实验更新。

当时运行时使用 `/api/chat`，将 JSON Schema 放入 `format`，设置 `temperature=0.2`、`num_predict=4096`、`num_ctx=32768`，并验证返回结构。这个调用方式符合 Ollama 的结构化输出接口；结构合规仍须与业务语义正确分开评价。协议依据：[Ollama 结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)。

## 适配判断

| 模型 | 对现有协议的适配 | 实施判断 |
| --- | --- | --- |
| Qwen3 4B | 接入前代码默认基线 | 保留相同提示词、Schema 和样本作为比较基线。 |
| Qwen3 8B | 同系列 chat/指令接口 | 可做质量对照，但更多参数不等于本项目必然更准或更快。 |
| Qwen3.5 4B | 通用指令模型，可沿用结构化 chat 思路 | 新模型中最适合优先进行原代码替换测试；需确认本机 Ollama 兼容性与实际结果。 |
| Tev1 4B | 专用决策协议与现有多目标索引输出存在明显差异 | 不建议直接改默认模型；适合作为另一路分类器实验。 |

以上是根据接口和任务结构作出的工程推断，不是准确率排名。Qwen3 官方说明包含多语言指令能力；Qwen3.5 模型卡说明多语言覆盖，并支持关闭默认思考。它们没有证明本项目中文否定、纠正、指代及字段归属的正确率。来源：[Qwen3 官方分发说明](https://ollama.com/library/qwen3:4b)、[Qwen3.5 4B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)。

## Tev1 的关键协议差异

Together 的原生约定是输入 `state`、`question`、2–24 个带字母的 `options`，返回一个选项字母，再由应用映射为业务标签；建议关闭思考、温度为 0。官方明确表示普通聊天不是预期用法，且多语言表现尚未充分评估。因此，单字母输出可靠不能等同于中文多意图 JSON 索引提取可靠。来源：[Together 官方模型卡](https://huggingface.co/togethercomputer/Tev1-4B-experimental)。

Ollama 为它提供 `/v1/systemone`：支持选择题、真假概率、等级评分；服务层把决策整理为 JSON。它要求 Ollama 0.35 或更新版本，默认上下文约 2,000 tokens，标签参数为 `num_ctx=2050`。这一 JSON 响应不是当前任意 JSON Schema 的等价接口。来源：[Tev1 官方 Ollama 使用说明](https://ollama.com/library/tev1:4b)。

若后续接入 Tev1，可将“是否存在某意图”“某片段是否属于某字段”拆成决策，再由 Python 组装结果；但同类多目标区分、跨片段归属、请求次数和总延迟都要重新验证。仅测它在现有 `/api/chat` 流程的失败率，只能说明直接替换不适配，不能推断其按原生协议运行的分类水平。

建议先比较 Qwen3 4B、Qwen3 8B、Qwen3.5 4B 的端到端通过率、意图数/类型、字段索引精确率与召回率、首轮成功率、重试次数和延迟；Tev1 的原生协议实验应单独报告。所有速度结论以本机相同负载实测为准。


## 本机安装与实测结果

已通过 Ollama 下载 `tev1:4b`（4.5 GB、Q8_0）和 `qwen3.5:4b`（3.4 GB、Q4_K_M）。原有 `qwen3:4b` 和 `qwen3:8b` 均保留。为支持 Tev1，Ollama 从 0.32.15 升至 0.35.0；官方更新包 SHA-256 与应用签名均已校验。旧应用备份保留在本机 Ollama 备份目录，不随仓库发布。

机器为 Apple M5、16 GB 内存。生产代码、v7 提示词、默认模型和评分器均未修改；63 个单元测试通过。下表全部使用同一生产源码哈希、同一 24 条公开开发题和 Ollama 0.35.0。`think=false`、`temperature=0.2`、`num_ctx=32768`、`num_predict=4096`、最多两次管线尝试、单次请求超时 120 秒。模型调用串行；未读取或执行隐藏验收。

| 模型 | 严格端到端通过 | 单题耗时中位数 | 单题平均耗时 | 运行错误题数 |
| --- | ---: | ---: | ---: | ---: |
| Qwen3 4B | 16/24 (66.7%) | 7.74 秒 | 7.83 秒 | 0 |
| Qwen3 8B | 20/24 (83.3%) | 29.40 秒 | 28.29 秒 | 0 |
| Qwen3.5 4B | 11/24 (45.8%) | 13.59 秒 | 12.69 秒 | 0 |
| Tev1 4B | 13/24 (54.2%) | 14.21 秒 | 24.25 秒 | 1 |

单题耗时包括两阶段调用、可能的模型加载与重试；不是纯推理速度。系统负载未固定，8B 运行时观察到约 15 GB 交换空间使用量，因此耗时仅代表本次机器状态。单轮、非零温度、公开开发集结果不代表稳定准确率或泛化表现。模型的其他默认参数沿用各自标签；例如 Qwen3.5 的 presence_penalty=1.5 未统一覆盖，因此衡量的是当前代码直接接入效果，不是隔离架构与采样参数的实验。

### 审查集与独立诊断

- Qwen3 4B：额外审查集 **9/19**，两组完整集共 **25/43**。
- Qwen3.5 4B：额外审查集 **10/19**，两组完整集共 **21/43**。
- Qwen3 8B：审查集只完成 **5/19**，其中 **3 条通过**。由于单题 42–55 秒并影响系统响应，停止扩展测试并卸载运行模型。不得将 3/5 当作完整审查成绩，也不能把其 29 个已完成样例与其他模型的 43 题直接排名。
- Tev1：未跑完整额外审查集。原生 `/v1/systemone` 单独进行了 43 条**顶层类别**诊断，**37/43**，中位数 **1.677 秒**。它不生成多目标实例、子类型、原文索引、字段或最终 Task，不能与上面的端到端通过率横向比较。
- Tev1 三题直接替换烟测为 2/3，随后才执行表中的完整 24 题。**它技术上可以生成当前 JSON Schema；任务形式不匹配不能等同于 API 不兼容。** 但完整测试一个多意图样例在约 245 秒后超时失败，说明原生快速单选优势没有直接转化为完整提取的稳定性。
- 升级前的 Qwen3 4B 为 19/24、9/19，单独保存在无 `_035_` 的文件中。运行环境变化且单轮采样有波动，不用于本表，也不据此归因升级导致性能变化。

### 当时对接入前代码的建议

1. **交互默认继续用 Qwen3 4B。** 本轮 24 题中位耗时最低，但仍有字段漏提、多标、否定/背景误判；不能将结构校验当作业务语义正确。
2. **准确性优先时选择 Qwen3 8B。** 同题 20/24 最好，适合容忍较高延迟的离线复核；16 GB 机器当前负载下内存与响应代价明显，仍不满足全部题通过。
3. **Qwen3.5 4B 暂不直接替换。** 可沿用现有接口，运行内存观测约 4.3 GB，但本轮 11/24，常见问题是把附属条件或同一咨询拆成多个目标、字段漏提与多标。若继续探索，应另开固定参数/提示适配实验，并完整回归。
4. **Tev1 适合独立分类器实验，暂不替代完整流程。** 原生决策很快，但仍在多意图和条件/否定背景上错分；直接提取为 13/24 且有超时。若接入，应明确增加 `/v1/systemone` 适配层与结果映射，并单独处理多目标拆分、片段归属和字段提取；不能仅把 `num_predict` 改成 8 就承接当前 JSON 输出。

该轮实验时 CLI 已可通过 `--model qwen3.5:4b` 或 `--model tev1:4b` 选择新模型；网页从 Ollama 模型列表动态加载，刷新后可选择。当时默认仍为 `qwen3:4b`，该轮实验未改动应用行为；当前默认配置以项目 README 为准。
